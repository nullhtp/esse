# esse — план реализации

От пустого репозитория до полного конвейера «искра → публикация».
Основание — [CONCEPT.md](CONCEPT.md); процесс — OpenSpec (см. [README.md](README.md)).

---

## Принципы

1. **Сначала убить главный риск.** Live-рендеринг markdown — самая дорогая часть
   проекта. Пока не доказано, что «ощущение Typora» достижимо на выбранном
   фреймворке, всё остальное строить рано.
2. **Каждый этап заканчивается приложением, которым можно пользоваться.**
   Продукт «для себя» — значит, догфудинг с первых недель: сначала копилка искр
   (дёшево, полезно сразу), потом письмо, потом полный конвейер.
3. **Один этап = одно OpenSpec-изменение** (`/opsx:propose` → `/opsx:apply` →
   `/opsx:archive`), задачи по ≤2 часа.

---

## Этап 0 — Прототип редактора и выбор фреймворка (~2–3 недели)

Один и тот же прототип на двух кандидатах, таймбокс ~1 неделя на каждый:

- **gpui** первым — самый высокий потолок по работе с текстом (движок Zed);
  если получится, «ощущение Typora» гарантировано.
- **iced** вторым — запасной вариант со стабильным API; редакторский виджет
  придётся писать поверх cosmic-text.
- **egui** не прототипировать вовсе — только если оба провалятся, тогда
  пересматривать подход в целом.

Критерии успеха прототипа (они же — критерии выбора):

- набор текста без лагов, кириллица и IME работают;
- `#`, `*курсив*`, `**жирный**` рендерятся на месте, маркеры скрыты вне текущей
  строки (поведение Typora);
- typewriter-режим: курсор держится по центру экрана;
- выделение, копипаст, undo не разваливаются;
- субъективный тест: «в этом хочется писать 20 минут».

Markdown-lite сильно упрощает задачу — нужны только заголовки и два
инлайн-стиля, полный CommonMark-рендеринг не нужен (парсер спанов можно
написать руками или взять pulldown-cmark только для разбора). Код прототипов —
в `prototypes/`, решение фиксируется в design-документе первого «настоящего»
изменения.

## Этап 1 — Скелет приложения, модель данных, копилка искр (~1 неделя)

- Доменная модель: `Spark`, `Essay` (состояния Draft → Editing →
  Published / Shelved), `Session`. **Инвариант WIP = 1 — в слое хранения**,
  не в UI.
- Хранилище — простые файлы в директории данных: `essays/<slug>.md` с TOML
  front matter (статус, даты, ссылка на публикацию), искры и сессии — JSONL.
  Человекочитаемо, переживёт любой рефакторинг, синхронизируется чем угодно;
  SQLite — только если файлов станет мало.
- Минимальный экран «Сегодня»: строка ввода искры + список искр. С этого
  момента приложение уже приносит пользу каждый день — копилка наполняется
  материалом для догфудинга.

## Этап 2 — Режим «Пишу»: сердце приложения (~2–4 недели)

- Прототип из этапа 0 превращается в боевой виджет редактора: автосохранение
  на каждую паузу, устойчивость к большим текстам.
- Старт эссе только из искры (кнопка «Писать» → выбор искры; если слот занят —
  эссе продолжается). Экрана «пустой документ» не существует — проверяется
  на уровне маршрутизации.
- Typewriter-режим, полноэкранность, тихий таймер сессии в углу с мягким
  завершением. Сессии пишутся в историю уже сейчас — календарь-пунктир
  появится позже.
- Ограничение правки назад — **только неудобством** (виден лишь текущий
  фрагмент), без механического запрета курсора: это проще, а ужесточить можно
  после личной проверки.

После этого этапа конвейер работает наполовину: искра → черновик, можно писать
по-настоящему.

## Этап 3 — Режим «Правлю» и переключение (~1–2 недели)

- Полный текст, спокойная вёрстка, обычная навигация и правка.
- Переключение «Пишу / Правлю» — явное действие; режимы визуально контрастны
  (например, тёмный поток против светлой вёрстки), чтобы разделение процессов
  чувствовалось телом.

## Этап 4 — Публикация и Полка: конвейер замыкается (~1–2 недели)

- Завершение эссе: **«Опубликовано»** (копировать как markdown + экспорт
  в файл — оба тривиальны, делаются сразу; поле «ссылка на публикацию»)
  или осознанно **«в стол»**.
- Экран «Полка»: Искры | В работе | Опубликовано + свёрнутый «стол». Из искры
  можно стартовать эссе, только если слот свободен.
- Освобождение слота WIP при публикации / «в стол».

**С этого момента приложение полностью выполняет свою миссию** — можно пройти
«первую неделю» из концепции на себе.

## Этап 5 — Ритм и витрина (~1 неделя)

- Пунктир сессий за последние недели на «Сегодня» — без стриков и чувства вины.
- Ряд опубликованных эссе карточками — главная витрина прогресса.

## Этап 6 — Доводка по итогам догфудинга (по мере надобности)

- Онбординг первого запуска: просьба записать 3–5 искр — единственный онбординг.
- Полировка типографики, хоткеи, скорость запуска (для «искры за 5 секунд»
  приложение должно открываться мгновенно — возможно, потребуется быстрый
  показ окна ввода искры).
- Ревизия открытых вопросов концепции на живом опыте: не ослабить ли WIP,
  не ужесточить ли «Пишу».

---

## Рекомендации по открытым вопросам

Зафиксированы здесь, чтобы не решать их в коде:

| Вопрос | Рекомендация |
|---|---|
| Фреймворк | Решает этап 0: gpui, если критерии взяты; иначе iced |
| Жёсткость WIP-лимита | Жёсткий запрет — как и сказано в концепции, ослабить проще |
| Экспорт | И копирование, и файл — оба дешёвые, вопрос снимается |
| Правка назад в «Пишу» | Только неудобством; механический запрет — эксперимент после догфудинга |

---

## Итого

До полного конвейера — примерно 2–3 месяца в режиме part-time. Польза
от приложения начинается уже с этапа 1, а главный технический риск снимается
в первые две-три недели.
